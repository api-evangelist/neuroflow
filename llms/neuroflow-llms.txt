## What is callable

NeuroFlow's platform API is real but **customer-only**. The NeuroFlow Live web and
mobile applications call a same-origin REST API at `https://neuroflowlive.com/api/`
(versioned `/api/v2/` routes, served by gunicorn). The service publishes a Swagger
document at `/api/swagger.json`, but anonymous requests to it return:

```
HTTP/2 401
content-type: application/json

{"message": "Please log in to continue", "code": 0}
```

The same route and the same 401 were observed on the sandbox, QA, staging and dev
environments. There is no public developer portal, no anonymous OpenAPI/Swagger,
no GraphQL endpoint, no MCP server, and no A2A agent card on any NeuroFlow host.

- [NeuroFlow Live API base](https://neuroflowlive.com/api/): session-authenticated REST API behind the NeuroFlow Live applications. Contract gated (401).
- [Swagger document (gated)](https://neuroflowlive.com/api/swagger.json): exists, returns 401 to anonymous callers.

## Notes for agents

- `www.neuroflow.com` is fronted by a SiteGround bot-challenge that answers HTTP 202
  with a `/.well-known/sgcaptcha/` redirect for every path, including `/robots.txt`
  and `/sitemap.xml`. Marketing and legal pages are indexed by search engines but are
  not directly fetchable by a plain HTTP client.
- `api.neuroflow.com`, `developer.neuroflow.com`, `docs.neuroflow.com`,
  `app.neuroflow.com` and `trust.neuroflow.com` are wildcard DNS entries that serve
  the same challenge under a certificate valid only for `neuroflow.com` /
  `www.neuroflow.com`. None of them is a developer surface.
- `api.neuroflowlive.com` resolves to CloudFront but fails the TLS handshake — a
  dangling record, not an API host.
- On `neuroflowlive.com`, every unrecognised path returns HTTP 200 with a 1,579-byte
  single-page-app HTML shell. Do not treat a 200 from that host as evidence a
  document exists; check `content-type`.
